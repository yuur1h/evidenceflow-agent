# 第二步：证据充分性与补救流程

## 行为变化

- 节点新增 partial 状态。非 resolved、没有有效来源链接、仍有开放问题或冲突的节点不会记为 success，也不会解锁依赖它的节点。
- 覆盖判定使用每个节点最新一次结果，同时要求成功状态和至少一条非空 claim + HTTP(S) URL。节点标签本身不能证明覆盖。
- official 维度还要求证据标记为 primary；recency 维度要求证据日期在计划的 scope.date_start/date_end 内。日期采用 YYYY-MM-DD，未明确范围、无效日期、超出范围或未来截止日期均不通过。
- 不再因已有候选答案而绕过核验、来源、时效缺口。所有模式保留未解决冲突，不用候选名称字符串过滤冲突。
- 下游阻塞时先在 max_replans 预算内重新规划并重试失败/部分完成节点，预算耗尽后才跳过仍阻塞的节点。最新结果替换旧失败结果的当前判定，历史事件仍保留。
- 增加 metadata.research_status（complete/partial/failed）和 coverage_complete。运行结束不等于研究完成。
- 不充分的多跳问答返回“证据不足，暂无法确定答案”，候选仅保留在报告 candidate_answer。报告模式加未完成提示；置信度上限 0.35 是保守产品规则，不是校准后的正确概率。
- 页面显示 partial 节点和未完成状态。

## 验证范围与限制

使用离线模拟模型/工具测试，无真实模型费用。覆盖无证据、partial、失败、有效来源、未解决冲突、日期范围、依赖阻塞、失败后恢复及预算耗尽。

本步只做结构性准入：URL 格式有效不代表网页真实存在或支持 claim；primary 仍来自证据元数据。逐条引用与原文一致性留给第三步。日期范围由规划器从用户问题提取，范围理解正确性仍需真实评测。对反证搜索无结果的情况目前保守保留 partial，不把“没找到”当作证明。

运行：`.\.venv\Scripts\python.exe -m pytest tests -q`
